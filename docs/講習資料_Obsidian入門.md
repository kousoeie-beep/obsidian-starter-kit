# Obsidian 入門 — 開いた瞬間から書ける状態を作る

対象：非エンジニア中心
所要：90分（手を動かす時間を含む）

> **講師メモ**は引用ブロックで書いています。配布時は削除するか、そのまま渡しても構いません。

## 前日までに済ませておくこと（受講者へ事前連絡）

当日ここでつまずくと、全体が20〜30分ずれます。**必ず前日までに。**

1. **Obsidian をインストール**（無料）https://obsidian.md
2. **Claude Code をインストールして、一度起動してログインまで済ませる**
   https://claude.com/product/claude-code

4. 起動できたことを、事務局に一言返信

> ここが完了しているかを、開始前に挙手で確認する。未完了者は補助者につける。

今日は Obsidian の**機能を覚えません**。
やることは3つだけです。

1. 自分の vault（ノートの入れ物）を作る
2. 「書く・つなぐ・探す」の3操作を覚える

> 講師メモ：ここで「機能を全部教えない」と最初に宣言しておく。

## 1. なぜ Obsidian なのか（10分）

### ノートが「ただのファイル」である

Obsidian で書いたノートは、パソコンの中の普通のテキストファイル（`.md`）です。
Finder やエクスプローラーで開けます。**Obsidian が無くなっても読めます。**

これを Obsidian の作者は **「file over app（アプリよりファイル）」** と呼んでいます。

### Notion との違い

| | Obsidian | Notion |
|---|---|---|
| データの置き場所 | **自分のパソコン** | 会社のサーバー |
| サービス終了したら | 手元に残る | 取り出す作業が要る |
| 複数人での同時編集 | 苦手 | 得意 |
| AI に読ませる | **フォルダごと渡せる** | API 経由 |
| 料金 | 個人は無料 | 人数課金 |

どちらが優れているかではなく、**役割が違います。**
5〜50人の会社でよくある落としどころは「**共有は Notion、個人の深掘りは Obsidian**」です。

> 講師メモ：ここで「今日から Notion をやめましょう」とは言わない。
> 併用が現実解。対立軸にすると導入の抵抗が増える。

### 会社で使ってよいのか

はい。**2025年2月から商用ライセンスが必須ではなくなりました**（任意の支援ライセンスに変更）。
業務で使っても課金義務はありません。

## 2. まず作る（20分・手を動かす）

### 手順1：ターミナルを開く

- **Mac**：`Command + Space` →「ターミナル」と打って Enter
- **Windows**：スタートメニュー →「**PowerShell**」

> 講師メモ：ここが最初の関門。黒い画面に抵抗がある人が必ずいる。
> 「今日は3回しか使いません。1行貼るだけです」と先に言う。
> **Mac と Windows で貼る文字列が違う**ので、スライドは必ず両方を出す。
>
> ⚠️ **Windows 版インストーラ（install.ps1）は Windows 実機での動作確認が未了。**
> 事前に1台で通しておくこと。通っていない場合、**Windows 参加者には最初から ZIP を渡す**
> （付録A「最後の手段：ZIP 配布」）。当日ぶっつけで試さない。

### 手順2：1行貼る

**Mac の人**

```bash
curl -fsSL https://raw.githubusercontent.com/kousoeie-beep/obsidian-starter-kit/main/install.sh | bash
```

**Windows の人**

```powershell
[Net.ServicePointManager]::SecurityProtocol=[Net.SecurityProtocolType]::Tls12; irm https://raw.githubusercontent.com/kousoeie-beep/obsidian-starter-kit/main/install.ps1 | iex
```

これで、Claude Code に Obsidian 用のコマンドが追加されます。

### 手順3：vault を置く場所を作って、そこで Claude Code を起動する

**Mac**

```bash
mkdir ~/Documents/my-vault
cd ~/Documents/my-vault
claude
```

**Windows**

```powershell
mkdir $HOME\Documents\my-vault
cd $HOME\Documents\my-vault
claude
```

> 講師メモ：`mkdir`（フォルダを作る）と `cd`（そこへ移動する）の2語だけ意味を説明する。
> 「フォルダを作って、その中に入った」と日本語で言い換えれば十分。
> **必ず新しい空フォルダを作らせる。** `Documents` の直下でそのまま `claude` を起動すると、
> 書類フォルダ全体が vault になりかける（コマンド側で止まるが、混乱するので先に防ぐ）。

### 手順4：`/vault-init` と打つ

```
/vault-init
```

聞かれるのは **1問だけ**です。

> この vault は何のために使いますか？

自分の言葉で答えてください。**今日はこの2つのどちらかで答えてください。**

- 「**仕事のメモと議事録をためたい**」
- 「**勉強したことを忘れないようにしたい**」

答えると、フォルダ・テンプレート・設定・最初に読むノートまで、**まとめて出てきます。**

> 講師メモ：**今日は答えを2択に誘導する。**
> このキットは5種類の型を持っていて、用途によってフォルダ構成もデイリーノートの有無も変わる。
> 自由に答えさせると全員の画面が揃わず、この後の演習（受信箱に書く・デイリーノートを開く）が
> 成立しない人が出る。**型の使い分けは講師デモで見せるだけにする。**

### 手順5：Obsidian で開く

Obsidian を起動 → 「**フォルダを vault として開く**」→ さっき作ったフォルダを選ぶ。

> 講師メモ：ここで全員の画面が揃う。揃わない人が出たら、
> 「vault として開く」を選べているか（「新規 vault を作成」を押していないか）を確認する。

## 3. 3つだけ覚える（20分・手を動かす）

### ① 書く

`Cmd + N`（Windows は `Ctrl + N`）で新しいノート。

**保存ボタンはありません。** 打った瞬間に保存されています。

> **やってみる：** 今日あったことを1行書いてください。

### ② つなぐ ← ここが本番

本文で `[[` と打つと、他のノートの候補が出ます。

**まだ無いノートの名前を書いても構いません。** 後から作られます。

リンク先のノートを開くと、下に「**バックリンク**」が出ます。
そのノートを参照している場所が、全部並びます。

> **やってみる：** 今書いたノートの中の名詞を1つ選んで `[[ ]]` で囲み、クリックしてください。

**これが Obsidian の主役です。**
フォルダに入れると1か所にしか置けませんが、リンクなら何か所からでもたどり着けます。

> 講師メモ：ここで「なるほど」と言わせられるかが分かれ目。
> 「田中さん」のノートを開くと、田中さんが出てきた議事録が全部並ぶ、という例が一番効く。
> 実際にその場でやって見せる。

### ③ 探す

覚えるキーは3つだけです。

| キー | 何が出るか |
|---|---|
| `Cmd + O` | ノート名で開く |
| `Cmd + Shift + F` | 全ノートの本文を検索 |
| **`Cmd + P`** | **やりたいことを日本語で打つと機能が出る** |

> **やってみる：** `Cmd + P` を押して「デイリー」と打ってください。

> 講師メモ：`Cmd + P` は最も費用対効果が高い。
> これを覚えると「操作が分からない」で止まらなくなる。ここだけは全員できるまで待つ。

## 4. AI と組む（25分）

### 前提：MCP の設定は要りません

2025年までの解説記事の多くは「MCP サーバーを立てる」と書いていますが、**今は不要です。**
vault のフォルダで `claude` と打つだけで、Claude Code はそのフォルダ全体を読めます。

### 使えるコマンド

| コマンド | 何が起きるか |
|---|---|
| `/vault-guide` | 使い方を、**今の自分の vault の中身に合わせて**教えてくれる |
| `/vault-save` | 今の会話の中身をノートにして残してくれる |
| `/vault-ask` | 「あの件どうだっけ」を**自分のノートの中から**答えてくれる |
| `/vault-lint` | リンク切れ・散らかりを点検してくれる |

> **やってみる：** Claude Code に何か相談して、`/vault-save` で残してみてください。

### `/vault-ask` の何がいいのか

普通に AI に聞くと、**AI が学習した一般論**が返ってきます。
`/vault-ask` は**自分が書いたノートだけを根拠に**答え、どのノートに書いてあったかを示します。

書いていないことは「vault には書かれていません」と言います。ここが重要です。

> 講師メモ：ここが today のクライマックス。
> 「検索」と「自分の記録から答える」の違いを実演で見せる。
> 同じ質問を（a）素の Claude と（b）`/vault-ask` に投げて、答えを並べると差が出る。

### さらに：Obsidian CLI（2026年2月の新機能）※今日は見るだけ

Obsidian の 設定 → General → **Command line interface** を有効にすると、
Claude Code が **Obsidian そのもの**を操作できるようになります。

```bash
obsidian search query="議事録"
obsidian daily:append content="- [ ] 明日やること"
obsidian backlinks file="田中さん"
```

無料です。ただし **1.12.7 以降のインストーラ**が必要で、アプリの自動更新だけでは足りないことがあります。
Mac では登録時に管理者パスワードを求められ、その後ターミナルの再起動が必要です。

> 講師メモ：**今日は各自にやらせない。講師デモだけ。**
> 管理者権限・再インストール・ターミナル再起動が絡み、全員でやると確実に時間が溶ける。
> 内容としては、2026年2月に出たばかりで日本語の解説がほとんどない。
> 「去年の記事に書いてあることは、もう古い」という話として出すと印象に残る。

### ⚠️ 注意が2つ

**① AI に書かせる vault と、自分の考えを書く vault は分けたほうがいい。**

混ぜると「これは自分が考えたことか、AI が書いたことか」が分からなくなります。
Obsidian の作者も同じことを言っています。

**② Claude に読ませたノートの中身は、AI の処理のために送信されます。**

ノートのファイル自体は自分のパソコンの中にありますが、
`/vault-ask` や `/vault-save` を使うと、その内容は Claude に渡ります。

**今日の演習では、本物の機密情報・個人情報を使わないでください。**
業務で使う際は、社内の AI 利用ルールを先に確認してください。

> 講師メモ：ここを飛ばさない。
> 「ローカルに保存される」と「AI に送られない」は別の話で、混同されやすい。
> 会社での導入判断では、Obsidian のライセンスより**こちらのほうが現実的な争点**になる。

## 付録A：うまくいかないとき

| 症状 | 対処 |
|---|---|
| `curl` の行でエラーが出る | ネットワークを確認。社内プロキシがある場合は情シスに確認。ダメなら**ZIP 配布**に切り替える（下記） |
| Windows で `curl -fsSL` が動かない | Windows は `curl` ではなく **`irm ... \| iex`** を使う。手順2の Windows 用を貼る |
| Windows で `git が見つかりません` | https://git-scm.com/download/win を入れて PowerShell を開き直す |
| Windows で接続エラー・無反応になる | 古い PowerShell 5.1 は TLS1.2 が既定でないことがある。**手順2の1行は先頭の `[Net.ServicePointManager]...` から全部貼る**（ここが抜けると無言で失敗する） |
| Windows で「スクリプトの実行が無効」と出る | ファイルから実行するときは `powershell -ExecutionPolicy Bypass -File ...` を使う。インストールの1行（`irm \| iex`）はこの制限を受けない |
| `claude` と打っても動かない | Claude Code が未インストール → https://claude.com/product/claude-code |
| `/vault-init` が出てこない | インストールの1行をもう一度実行。**Claude Code を一度終了して起動し直す** |
| `同じ名前のファイルが既にあります` と出て止まる | 以前に自分で作ったコマンドがある。**その場では無理に上書きしない**。補助者を呼ぶ |
| Obsidian で開いたら空っぽ | 「新規 vault を作成」ではなく「**フォルダを vault として開く**」を選ぶ |
| 設定が元に戻ってしまう | Obsidian を起動したまま設定を書き込むと上書きされる。一度終了してからやり直す |
| デイリーノートにテンプレートが当たらない | `Templates/デイリーノート.md` があるか確認。無ければ作る |
| スマホと同期したい | Mac/iPhone だけなら iCloud。Windows が混ざるなら Obsidian Sync（有料）を勧める |

### 最後の手段：ZIP 配布

インストールがどうしても通らない人には、**完成済みの vault を ZIP で渡す**。
Obsidian で「フォルダを vault として開く」だけで、3章以降の演習に合流できます。

> 講師メモ：当日は必ず ZIP を USB か共有ドライブに用意しておく。
> ネットワーク障害・GitHub 障害・プロキシのいずれか1つで、インストール導線は全滅しうる。
> 「作る体験」より「全員が同じ画面に揃うこと」を優先する。

## 付録C：フォルダ構成の流派（聞かれたら）

| 流派 | 考え方 |
|---|---|
| PARA | Projects / Areas / Resources / Archives の4分類。世界で最も普及 |
| Zettelkasten | フォルダを作らず、小さなノートを大量にリンクする |
| LYT / MOC | 「フォルダで整理するのをやめて、リンクで整理する」 |
| 数字プレフィックス | `01_` `02_` で並び順を固定する |

**今日作った構成は、この4つのいいとこ取り**（数字プレフィックスで並べ、リンクでつなぎ、フォルダは最小）です。
最初からどれかを完全に真似する必要はありません。
