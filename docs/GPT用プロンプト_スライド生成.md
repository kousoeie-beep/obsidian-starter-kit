# GPT 用プロンプト：Obsidian 研修スライド生成

**使い方：下の区切り線から下を全部コピーして GPT に貼ってください。**
出力形式を変えたい場合は、末尾の「## 出力形式」だけ書き換えてください。

---

あなたは企業研修のプレゼン資料を設計・執筆するプロです。
以下の仕様で、非エンジニア向けのスライドを作ってください。

## 前提

- **テーマ**：Obsidian（メモ・ナレッジ管理アプリ）で作った「vault」の管理方法と使い方
- **受講者**：非エンジニア。Obsidian は初見。ターミナルもほぼ触らない
- **状況**：受講者の手元には**すでに完成した vault がある**（作る作業は終わっている）。今日はその使い方を学ぶ
- **時間**：説明 30〜35 分（手を動かす時間は別枠）
- **枚数**：本編 27 枚＋付録 7 枚

## 前提知識（これを踏まえて書くこと）

受講者の vault は次の構成になっています。

```
01_受信箱/        行き先が決まっていないもの。何でもここ
02_議事録/        MTGごとに1ノート
03_案件/          案件ごとに1ノート
04_手順書/        やり方
05_人と組織/      取引先・社内メンバー
Templates/        ひな形（触らない）
Attachments/      画像・PDF（自動で入る）
00_はじめに.md    最初に読むノート
CLAUDE.md         AI向けのルール（人は読まなくていい）
_ログ.md          AIが作業履歴を1行ずつ追記する（人は書かない）
_いまの文脈.md    AIが次回への引き継ぎを書く（人は書かない）
議事録一覧.base   議事録が並ぶ表
案件一覧.base     案件が並ぶ表
```

Obsidian の重要な性質：

- ノートは**自分のPCの中の普通のテキストファイル**。サービスが終わっても残る
- 本文に `[[名前]]` と書くと**リンク**になり、リンク先のページ下部に「**バックリンク**」として逆引きが自動で出る
- **フォルダは1か所にしか置けないが、リンクなら何か所からでも辿れる**。これが最大の利点
- `.base` ファイルで表（データベース風の一覧）が作れる。**追加インストール不要・クエリ不要**
- Claude Code（AIツール）と連携し、`/vault-save`（会話をノート化）`/vault-ask`（自分のノートだけを根拠に回答）`/vault-lint`（点検）`/vault-guide`（使い方を教わる）が使える

## 執筆の制約

1. **1枚1メッセージ。** 1枚に2つのことを言わない
2. **1枚の文字数は最大120字程度。** 話し言葉はノートに書く
3. **専門用語を出したら、その場で一言で言い換える**（例：「frontmatter（ノート先頭の設定欄）」）
4. **「〜するとよいでしょう」ではなく「〜してください」**と具体的に書く
5. キー表記は Mac 基本、Windows を括弧で添える（例：`Cmd+N`（Windows: `Ctrl+N`））
6. **機能の網羅をしない。** 運用（どう回すか）に集中する
7. 各スライドに**スピーカーノート**（講師が話す内容・3〜5行）を必ず付ける
8. スクリーンショットが必要な箇所は `【画像：〜の画面】` の形で指示だけ書く（画像は別途用意する）

## 全体の骨格

管理の4動作 **「入れる → 育てる → 取り出す → 保つ」** を軸にする。
**この循環図を全スライドの右上に小さく置き、現在地をハイライトする**（その旨をレイアウト指示として書く）。

## スライド構成（この通りに作ること）

### 第0章 全体像

1. **覚えることは4つだけ** — 「入れる→育てる→取り出す→保つ」の循環図。機能は覚えなくていいと宣言する
2. **できあがった状態から始めます** — vault 全画面。ゼロから設計しない、運用の話から入る

### 第1章 構造：どこに何があるか（速く流す）

3. **フォルダは7つだけ** — 深い階層を作らない設計。7つで足りるようにしてある
4. **7つは3種類しかない** — ①入口＝`01_受信箱` ②置き場＝`02〜05` ③裏方＝`Templates`/`Attachments`（触らない）。**この1枚がこの章の本体**
5. **自分で書かないファイルが2つ** — `_ログ.md` と `_いまの文脈.md`。AIが書く。詳細は第4章

### 第2章 入れる：置き場所に迷わない

6. **判断は2択だけ** — 「行き先が決まっている？ YES/NO」だけのフロー図。**分岐を増やさない**
7. **迷ったら受信箱** — 整理は後でいい。整理してから書こうとすると書かなくなる
8. **決まっているものは直接置く** — 議事録→`02_議事録`、案件→`03_案件` の対応表

### 第3章 育てる：溜めたものを使えるようにする

9. **名前のつけ方は1つだけ** — 日付は `YYYY-MM-DD` で固定（理由：並ぶから）。それ以外は日本語で自由
10. **人・会社・製品は `[[ ]]` で書く** — 3コマ構成（`[[` を打つ → クリック → バックリンクに出る）。**この講習の山場。厚く書く**
11. **フォルダとタグの使い分け** — フォルダ＝どこに属するか／タグ＝何についてか。迷ったらフォルダだけでいい
12. **書く量は気にしない** — 走り書き→AIが整えた後のBefore/After。きれいに書こうとして止まるのが一番損

### 第4章 AI と分担する

13. **人がやること / AIがやること** — 人＝書く・決める・選ぶ／AI＝整える・探す・記録する・点検する
14. **会話をそのままノートにする** — `/vault-save`。残す価値のある2割だけを選んで書いてくれる
15. **自分のノートから答えさせる** — `/vault-ask`。普通のAIは一般論を答えるが、これは自分が書いたことだけを根拠に、**どのノートかを示して**答える
16. **使うほど育つ** — `_ログ.md` の1日目→2週間後の比較。次に開いたとき前回の説明が要らない。**普通のメモアプリとの決定的な違い。ここを弱くしない**

### 第5章 取り出す：あとで見つける

17. **探し方は3つ** — `Cmd+O`／`Cmd+Shift+F`／`Cmd+P`。**`Cmd+P` だけは必ず覚える**
18. **辿って見つける** — バックリンクから3ノート先まで辿る経路図。検索で出なくても人や案件から辿れる
19. **表で見る** — `議事録一覧.base` と `案件一覧.base`（進行中/すべての切替）。追加インストール不要

### 第6章 保つ：散らからない運用

20. **やることは週1と月1だけ** — 週1：受信箱を空にする／月1：`/vault-lint`。**これ以上の管理はしないと約束する**
21. **週1：受信箱を空にする** — 5分で終わる。**空にできなくてもいい。触るだけで十分**
22. **月1：AIに点検させる** — `/vault-lint` の結果（リンク切れ・孤立ノート・重複）。**直す前に一覧で見せる。勝手に消さない**
23. **フォルダを増やす基準** — 「同じ種類が3つたまってから」。先に器を作ると埋めるのが目的化する

### 第7章 シーン別：実際の1日

24. **会議のあと** — 議事録テンプレ挿入→参加者を `[[ ]]` で書く。3分で終わる
25. **案件を追う / 人から辿る** — 案件→関連議事録→人、と辿る経路。「あの件どうなってたっけ」が数秒で出る
26. **調べものを残す** — 相談→`/vault-save`→後日 `/vault-ask` で引き出す。調べ直さなくてよくなる

### 第8章 持ち帰り

27. **明日からやること3つ** — ①1日1行でいいので書く ②迷ったら受信箱 ③分からなくなったら `/vault-guide`

### 付録（本編の後ろに置き、質問が出たときだけ開く）

- A1. Notion との違い（併用が現実解。共有はNotion、個人の深掘りはObsidian）
- A2. スマホと同期したい（Mac/iPhoneはiCloud、Windows混在はObsidian Sync）
- A3. 会社で使っていいのか（2025年2月から商用ライセンスは任意になった）
- A4. `CLAUDE.md` とは（AI向けのルールブック。人は読まなくていい）
- A5. プラグインは入れないのか（最初は0個。起動が遅くなる。困ってから足す）
- A6. チームで使うには（共有vaultに個人メモを置かない・守秘レベルを書く）
- A7. うまくいかないとき（トラブル対応の一覧）

## 強弱のつけ方

- **厚く書く**：第2章（入れる）、第4章（AIと分担）、第6章（保つ）
- **速く流す**：第1章（構造）、第5章（取り出す）
- **最重要スライド**：10番（リンクとバックリンク）と16番（使うほど育つ）。この2枚が刺されば成功

## 出力形式

Marp 形式の Markdown で出力してください。

- スライドの区切りは `---`
- 各スライドは「# 見出し」＋本文（箇条書き中心）
- 画像が必要な箇所は `<!-- 【画像：〜の画面】 -->` のコメントで指示
- スピーカーノートは各スライド末尾に `<!-- speaker: 〜 -->` の形で入れる
- 冒頭に Marp のフロントマター（`marp: true`、`theme`、`paginate: true`）を付ける

まず**第0章から第3章まで（スライド1〜12）**を出力してください。
続きは「続き」と言われたら出します。
