# Obsidian の教え方

## 前提となる事実

Obsidian をやめる人は、**機能を知らないからやめるのではない**。
「書き始めるまでの設定が多い」「自由すぎて何をすればいいか分からない」でやめる。

だから教える順番はこうなる：**書く → つなぐ → 探す → ためる → 自動化する**。
この順番を飛ばさない。特に「つなぐ」より前に構成の話をしない。

## 段階の見分け方

vault の中身を見て判定する。聞かない。

| 段階 | 見分け方 | 教えること |
|---|---|---|
| 1. 書く | ノートが3本未満 | 新規作成、保存の概念（保存ボタンは無い）、どこに書くか |
| 2. つなぐ | ノートはあるが `[[` が0〜数個 | `[[`、バックリンク、存在しないノートへのリンク |
| 3. 探す | リンクはあるが検索を使った形跡がない | `Cmd+O`、`Cmd+Shift+F`、`Cmd+P` |
| 4. ためる | 20本以上あり、雑然としている | デイリーノート、テンプレート、タグ、Bases |
| 5. 自動化する | 運用が回っている | Claude Code 連携、Obsidian CLI、kepano のスキル |

判定に迷ったら**低いほうを選ぶ**。

---

## 段階1：書く

**教える前に、この vault に実際にあるフォルダを確認する。** 案内するフォルダ名は必ず実物に合わせる。
（`01_受信箱` が無い vault もある。AI ナレッジウィキ型では入口が `.raw/` と `wiki/` になる）

**伝える中身は3つだけ。**

1. `Cmd+N`（Windows: `Ctrl+N`）で新しいノート
2. **保存ボタンは無い。** 打った瞬間に保存されている
3. 迷ったら受信箱（この vault での入口フォルダ）に書く。整理は後

**やってもらう：** 今日あったことを1行書く。

> つまずきどころ：「どこに保存されたか分からない」。
> `新規ノートの作成場所` が設定済みなので、必ず決まった場所に入ると伝えて安心させる。

---

## 段階2：つなぐ（ここが山場）

**Obsidian の主役はここ。** フォルダではなくリンクで整理する。

1. ノートの本文で `[[` と打つと候補が出る
2. **まだ無いノートの名前を書いてもいい。** 後から作られる
3. リンク先のノートを開くと、下に**バックリンク**（そこから来ているノート）が出る

**やってもらう：** 今書いたノートの中の名詞を1つ選んで `[[ ]]` で囲む。
そのリンクをクリックして、新しいノートが作られるのを見てもらう。

> ここで「なるほど」と言わせられるかが分かれ目。
> 「フォルダに入れると1か所にしか置けないが、リンクなら何か所からでもたどれる」と伝える。

---

## 段階3：探す

覚えるのは3つのキーだけ。

| キー | 何が出るか |
|---|---|
| `Cmd+O` | ノート名で開く（名前の一部でよい） |
| `Cmd+Shift+F` | 全ノートの本文を検索 |
| `Cmd+P` | コマンドパレット。やりたいことを日本語で打つと機能が出る |

**やってもらう：** `Cmd+P` を押して「デイリー」と打ってもらう。

> デイリーノートが無効な vault（チーム共有型・AI ナレッジウィキ型）では「デイリー」を使わない。
> 「グラフ」や「テンプレート」で代替する。**その vault に無い機能を練習させない。**

> `Cmd+P` を教えると、以降「操作が分からない」で止まらなくなる。最も費用対効果が高い。

---

## 段階4：ためる

ここで初めて仕組みの話をする。

1. **デイリーノート** — 今日の日付のノートを一発で開く。「どこに書くか」問題が消える
2. **テンプレート** — 議事録などの型。`Cmd+P` →「テンプレートを挿入」
3. **タグ** — 本文に `#タグ名`。フォルダは「どこに属するか」、タグは「何についてか」
4. **Bases** — `.base` ファイルで一覧表を作る。Notion のテーブルのようなもの。**プラグイン不要**

**やってもらう：** デイリーノートを開いて、テンプレートを1回挿入する。

> フォルダを増やしたがる人には「同じ種類が3つたまってから」と伝える。
> 先に器を作ると、埋めることが目的になって続かない。

---

## 段階5：自動化する

1. **vault のフォルダでターミナルを開いて `claude`** と打つ。それだけで Claude Code が vault 全体を読める
2. `/vault-save` — 今の会話をノートにして残す
3. `/vault-ask` — vault の中から答えさせる
4. `/vault-lint` — リンク切れや孤立ノートを点検する
5. **Obsidian CLI**（設定 → General → Command line interface）を有効にすると、
   Claude Code が Obsidian そのものを操作できる。MCP の設定は要らない
6. もっと深く扱いたくなったら kepano/obsidian-skills（Obsidian 作者の公式スキル）を入れる

**必ず添える注意：** AI に書き足させる vault と、自分の思考を書く vault は分けたほうがいい。
混ぜると「これは自分が考えたことか、AI が書いたことか」が分からなくなる。

## よく来る質問への答え

| 質問 | 答え方 |
|---|---|
| Notion と何が違う？ | ノートが自分のパソコンの中の普通のテキストファイル。サービスが終わっても残る。逆にリアルタイム共同編集は苦手 |
| スマホと同期したい | Mac/iPhone だけなら iCloud が一番簡単。Windows が混ざるなら Obsidian Sync（有料）を勧める。iCloud で Windows と混ぜると別フォルダができて事故る |
| 無料で使える？ | 個人利用は無料。**2025年2月から商用ライセンスも任意（支援）になった**ので、会社で使っても課金義務は無い |
| フォルダ構成はどうすれば | 3〜5個で始める。PARA や Zettelkasten を最初から真似しない。運用してから寄せる |
| プラグインは何を入れる？ | 最初は0個。困ってから足す。入れすぎると起動が遅くなる |
| 書いたものが消えないか | ファイルは普通の `.md`。Finder でも開ける。設定で「ファイルリカバリー」も有効にしてある |
| Dataview は要る？ | いまは Bases（コア機能）で足りる。クエリ言語を覚えなくていい |

## 教えるときの禁止事項

- 一度に5個以上教える
- 相手が手を動かす前に次へ進む
- 「まず構成を設計しましょう」と言う
- 専門用語を言い換えずに使う
- 網羅的な機能一覧を出す
