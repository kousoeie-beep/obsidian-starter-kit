# 散らかった vault を整理する

**この skill はこのキットで最も危険な操作を行う。** 持ち主のファイルを移動する。
間違えれば取り返しがつかない。**急がない。飛ばさない。**

---

## 絶対に守ること

| 禁止 | 理由 |
|---|---|
| **削除しない** | 空フォルダも既定は残す。消すのは本人が明示的に指示したときだけ |
| **ファイル名を変えない** | 移動だけ。リネームはリンクを壊す |
| **中身を書き換えない** | 例外はパス付きリンクの修正のみ（後述） |
| **一度に全部やらない** | 承認された範囲だけ実行する |
| **黙って実行しない** | 必ず提案 → 承認 → 実行 |
| **迷ったものを勝手に動かさない** | 分類に確信が持てないファイルは**1件ずつ聞く**。既定は「動かさない」 |

> **一括承認だけで済ませない。** 「メモ/ の34件 → 受信箱」とまとめて聞くと、
> その中に混ざっている議事録も一緒に動く。**確信度で扱いを変える**（Step 4）。

---

## Step 0. 退避路を確保する（飛ばさない）

**元に戻せない状態で始めない。**

```bash
pgrep -x Obsidian    # 起動中なら終了してもらう（設定を書くため）
git -C . rev-parse --git-dir 2>/dev/null   # git 管理か
```

| 状況 | やること |
|---|---|
| Obsidian が起動中 | 「一度終了してください」と伝えて待つ |
| git 管理されている | `git status` で clean か確認。dirty なら**先にコミットしてもらう** |
| git 管理でない | **`git init` して現状を1回コミットすることを勧める。** 断られたら `.obsidian-starter-kit-backup-YYYY-MM-DD/` に全体をコピーしてから進む |

退避路が無いまま移動を始めない。**ここを飛ばしたら、この skill は失敗している。**

## Step 1. 散らかりを診断する（読むだけ・まだ動かさない）

**bash が使えるなら、同梱の診断スクリプトを実行するのが速い**（読むだけで何も変更しない）：

```bash
bash ~/.claude/skills/vault-organize/references/diagnose.sh /path/to/vault
```

Windows など bash が無い環境では、以下を1つずつ実行して同じことを調べる。

```bash
# 規模
find . -name "*.md" -not -path "./.obsidian/*" -not -path "./.git/*" | wc -l
find . -type d -not -path "./.obsidian*" -not -path "./.git*" | wc -l
find . -name "*.md" -not -path "./.git/*" | awk -F/ '{print NF}' | sort -rn | head -1

# ルート直下に散らばったノート
find . -maxdepth 1 -name "*.md" | wc -l

# 空のフォルダ
find . -type d -empty -not -path "./.obsidian*" -not -path "./.git*"

# 添付ファイルの散らばり
find . \( -name "*.png" -o -name "*.jpg" -o -name "*.pdf" \) -not -path "./.git/*" \
  | xargs -n1 dirname | sort | uniq -c | sort -rn | head

# ★ パス付きリンク（移動で壊れるのはこれだけ）
grep -rho "\[\[[^]]*/[^]]*\]\]" --include="*.md" . | wc -l
```

### 散らかりの型

| 症状 | 型 | 直し方 |
|---|---|---|
| ルート直下に `.md` が10件以上 | **置き場が無い** | 受信箱を作って移す |
| 3階層より深い | **深すぎる** | 2階層までに畳む |
| 空フォルダが複数 | **使われていない器** | 報告する（消さない） |
| 同種のノートが複数フォルダに散在 | **分類が二重** | 1か所に寄せる |
| 添付が10フォルダ以上に散在 | **添付置き場が未設定** | `Attachments/` に集約 |
| 日付形式がバラバラ | **命名ルールが無い** | **触らない。** 今後の書き方だけ伝える |

## Step 2. どこまでやるかを選ばせる（重要）

**「推奨構造に全部まとめる」を既定にしない。** 1000件のノートを5フォルダに押し込むのは
現実的でないし、持ち主の頭の中の分類を壊す。**段階を選ばせる。**

```
この vault には ノート 1033件 / フォルダ 343個 があります（最大12階層）。

どこまで整理しますか？

  1) 安全な整理だけ（おすすめ）
     ・ルート直下に散らばったノートを 01_受信箱 へ
     ・添付ファイルを Attachments/ に集約
     ・空フォルダを一覧で報告（消しません）
     → ノートの分類には手を付けません

  2) 分類も整理する
     ・1 に加えて、同じ種類のノートを1か所に寄せます
     ・寄せ先が無ければ作ります（最大5フォルダ）

  3) 推奨構造に作り替える
     ・すべてのノートを分類して配置し直します
     ・大きな vault では時間がかかり、分類が合わない箇所も出ます

  番号を選んでください（やめるなら Enter）:
```

**迷っている様子なら 1 を勧める。** 後から 2 に進める。逆は戻せない。

## Step 3. パス付きリンクを先に数える（ここを飛ばすと壊す）

Obsidian の `[[名前]]` は**パスを含まないので移動しても壊れない**。
だが `[[フォルダ/名前]]` の形式は**移動すると壊れる**。

```bash
grep -rn "\[\[[^]]*/[^]]*\]\]" --include="*.md" . | head -20
grep -rho "\[\[[^]]*/[^]]*\]\]" --include="*.md" . | wc -l
```

| 件数 | 対応 |
|---|---|
| 0件 | そのまま進んでよい |
| 1〜50件 | 移動後に**機械的に修正する**（下記） |
| 50件超 | **持ち主に伝えてから進む。** 「移動すると N 箇所のリンクを書き換えます」と件数を出す |

### 移動後の修正方法

`[[旧パス/名前]]` を `[[名前]]` に置き換える。
**パスを消すのが最も安全**（Obsidian は名前だけで解決できる。同名ファイルが無い限り）。

**まず同名チェックをする。同名があればパスを消してはいけない。**

```bash
find . -name "*.md" -not -path "*/.git/*" | sed 's|.*/||' | sort | uniq -d
```

同名が0件なら、一括でパスを落とす（**検証済みの手順**）：

```bash
grep -rl "\[\[[^]]*/[^]]*\]\]" --include="*.md" --exclude-dir=.git . \
  | while read -r f; do
      perl -CSD -pi -e 's/\[\[[^\]]*\/([^\]\/]+)\]\]/[[$1]]/g' "$f"
    done
```

> **`sed` ではなく `perl -CSD` を使う。** 日本語を含むパスでは `sed` のエスケープが壊れやすく、
> macOS(BSD) と Linux(GNU) で `-i` の書式も違う。`perl -CSD` は UTF-8 を正しく扱い、
> どちらでも同じ書き方で動く。

**同名が1件でもある場合は、そのノートだけ個別に新パスへ書き換える。** 一括で消さない。

### Windows の場合

`bash` が無い環境では、上のコマンドは動かない。同じことを PowerShell で行う。

```powershell
# 同名チェック
Get-ChildItem -Recurse -Filter *.md | Where-Object { $_.FullName -notmatch '\\\.git\\' } |
  Group-Object Name | Where-Object Count -gt 1

# パス付きリンクをパスなしに（同名が0件のときだけ）
Get-ChildItem -Recurse -Filter *.md | Where-Object { $_.FullName -notmatch '\\\.git\\' } | ForEach-Object {
  $t = Get-Content $_.FullName -Raw -Encoding UTF8
  $n = [regex]::Replace($t, '\[\[[^\]]*/([^\]/]+)\]\]', '[[$1]]')
  if ($n -ne $t) { Set-Content $_.FullName $n -NoNewline -Encoding UTF8 }
}
```

**`references/diagnose.sh` は bash 用。** Windows では実行せず、SKILL 本文のコマンドを
PowerShell に読み替えて1つずつ実行すること。

## Step 4. 分類の確信度で3つに分ける（ここが要）

**一括承認で済ませてはいけない。** 「メモ/ の34件 → 受信箱」とまとめて聞くと、
その中に混ざっている議事録も一緒に動く。**確信度で扱いを変える。**

| 確信度 | どういうものか | 扱い |
|---|---|---|
| **確実** | フォルダ名と中身が一致（`会議録/` にある `type: meeting` のノート）／frontmatter に `type` がある／ファイル名が `YYYY-MM-DD 〇〇` で本文に「決まったこと」がある | **まとめて確認**して動かす |
| **曖昧** | どちらとも取れる（案件の話も議事録の要素もある）／判断材料が少ない | **1件ずつ聞く** |
| **不明** | 分類の手がかりが無い／中身が短すぎる／持ち主にしか分からない | **動かさない。** 現状のまま残して報告する |

### 曖昧なものの聞き方

**1件ずつ、中身の要点を添えて聞く。** ファイル名だけ出しても判断できない。

```
判断に迷ったものが 7件あります。1つずつ確認させてください。

  [1/7] メモ/打ち合わせの件.md
        中身: 「田中さんと来期の予算について。3案を比較して…」
        更新: 2026-07-14

        1) 02_議事録 に移す
        2) 03_案件 に移す
        3) 01_受信箱 に移す
        4) このまま動かさない（既定）

        → 番号を入力（Enter で「動かさない」）:
```

**Enter を既定で「動かさない」にする。** 迷ったときに何もしないのが最も安全で、
持ち主が疲れて雑に Enter を連打しても事故にならない。

### 曖昧なものが多すぎるとき

**20件を超えたら、1件ずつは現実的でない。** その場合は先にまとめて聞く。

```
判断に迷ったものが 63件あります。どうしますか？

  1) 全部 01_受信箱 に移す（後で自分で振り分ける）
  2) 全部そのまま動かさない
  3) 1件ずつ確認する（63回聞きます）

  → 番号を入力:
```

### 実行中に迷ったら止まる

提案の時点で「確実」に分類したものでも、**動かす直前に違和感があれば止めて聞く。**
黙って進めない。1件のノートを失うより、1回聞くほうが安い。

## Step 4-2. 全体の提案を見せる（承認前に必ず）

**移動する前に、何をどこへ動かすかを全部見せる。**

**内訳は「何件」で終わらせず、確信度の根拠を1行添える。**
根拠が書けないものは、そもそも「確実」ではない。

```
こう整理します：

【確実に移せるもの】
  1) 会議録/ → 02_議事録         38件
     根拠: 全件に frontmatter の type: meeting がある
  2) 画像・PDF → Attachments/    298件
     根拠: 拡張子で判別。本文は変更しません
  3) ルート直下 → 01_受信箱      12件
     根拠: 置き場が無いだけなので、いったん受信箱へ

【1件ずつ確認するもの】 7件
  → このあと1つずつ聞きます（Enter で「動かさない」）

【動かさないもの】
  進行中/     47件  分類の手がかりがありませんでした
  .raw/       12件  原資料なので対象外
  .obsidian/  設定
  .git/       履歴

【報告だけ・消しません】
  空のフォルダ 3個: 旧メモ/、test/、下書き/

【リンクの書き換え】
  パス付きリンク 615箇所のうち、移動対象に関わる 89箇所を書き換えます
  同名ノートが 21件あるため、そこはパスを残します

【退避路】
  git でコミット済み（戻せます）

上の【確実】を実行してよいですか？
  はい / 番号で選ぶ（例: 1,3） / やめる
```

**「はい」以外は必ず番号で選ばせる。** 「一部だけ」と言われたら、
どの番号を実行するかを聞き返す。曖昧なまま進めない。

## Step 5. 実行する

**承認された範囲だけ**を、この順で行う。

1. 退避（git commit またはコピー）が済んでいることを再確認
2. **フォルダを作る**（移動先が無ければ）
3. **移動する。`mv` を素で使わない**（下記）
4. **パス付きリンクを修正する**（Step 3 の方法）
### 移動は必ず「上書きしない」形で行う

**`mv src dst/` は、移動先に同名があると黙って上書きする。** ノートが1件消える。
必ず存在を確かめてから動かし、ぶつかったものは**移動せずに報告する**。

```bash
move_safe() {
  local src="$1" dstdir="$2"
  local base; base=$(basename "$src")
  if [ -e "$dstdir/$base" ]; then
    echo "  衝突（移動しません）: $src → $dstdir/$base が既にある"
    return 1
  fi
  mv "$src" "$dstdir/"
}
```

PowerShell の場合：

```powershell
function Move-Safe($Src, $DstDir) {
  $base = Split-Path $Src -Leaf
  if (Test-Path (Join-Path $DstDir $base)) {
    Write-Host "  conflict (not moved): $Src"
    return $false
  }
  Move-Item $Src $DstDir
  return $true
}
```

**衝突したファイルは最後にまとめて報告する。** 勝手にリネームして動かさない。
どちらを残すかは持ち主が決めることで、AI が決めることではない。

5. **`.obsidian` の設定を新構造に合わせる**
   - `app.json` の `newFileFolderPath`
   - `app.json` の `attachmentFolderPath`
   - `daily-notes.json` の `folder`
6. **`00_はじめに.md` と `CLAUDE.md` を作る**（無ければ。フォルダ表は**実際の構造**に合わせる）
7. **`_ログ.md` に何をしたかを記録する**

## Step 6. 壊していないことを確かめる（必須）

**移動した後、必ず検証する。** 数が合わなければ止めて報告する。

```bash
# 1. ノートの数が変わっていないこと
find . -name "*.md" -not -path "./.obsidian/*" -not -path "./.git/*" | wc -l

# 2. リンク切れが増えていないこと（移動前の数と比べる）
grep -rho "\[\[[^]|#]*" --include="*.md" . | sed 's/\[\[//' | sort -u | while read -r n; do
  [ -z "$n" ] && continue
  find . -name "$n.md" | grep -q . || echo "切れ: [[$n]]"
done | wc -l

# 3. 設定の参照先が実在すること
node -pe "JSON.parse(require('fs').readFileSync('.obsidian/app.json','utf8')).newFileFolderPath"
```

| 検証 | 合格条件 |
|---|---|
| ノート数 | **移動前と同じ**。減っていたら即座に報告して復旧を提案 |
| リンク切れ | **移動前より増えていない** |
| 設定の参照先 | すべて実在する |

**1つでも不合格なら、git で戻すかバックアップから復旧することを提案する。**
黙って先に進まない。

## Step 7. 報告する

- 何を何件動かしたか（パス付きで）
- 書き換えたリンクの数
- **動かさなかったもの**とその理由
- 検証の結果（ノート数・リンク切れ・設定）

最後に**1つだけ**、次にやるとよいことを添える。並べ立てない。

---

## やらないほうがいいこと

- **深い階層を無理に潰さない。** 持ち主が意図して作った構造かもしれない。3階層以上でも、
  中身が整理されていれば触らない
- **ファイル名の日付形式を統一しない。** 既存ノートのリネームはリンクを壊す。
  「今後は `YYYY-MM-DD` で書くといい」と伝えるだけにする
- **frontmatter を一括で足さない。** 中身の書き換えは範囲を超える
- **`.raw/` の中身を動かさない。** 原資料は immutable
