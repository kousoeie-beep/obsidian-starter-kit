# vault を回す

すべての操作の前に **`CLAUDE.md` を読む**。この vault の目的・フォルダ・ルールがそこにある。
無ければ「まだ整っていない vault」として扱い、既存の構造を観察してから動く。

---

## 最初と最後に必ずやること

**この2つを飛ばすと、vault は「置き場」のままで育たない。**

**始めに** — `_いまの文脈.md` があれば読む。前回どこまでやったかを持ち主に説明させない。

**終わりに** — 次の2つを書く。これは持ち主ではなく**あなたが書く**。

| ファイル | 書き方 |
|---|---|
| `_ログ.md` | 今日の日付見出しの下に**1作業1行**で追記。関係ノートは `[[リンク]]` にする。**過去の行は消さない**（先頭が新しい） |
| `_いまの文脈.md` | **上書き**。500語以内。次に開いた自分への引き継ぎとして書く |

記録しないもの：検索しただけ・読んだだけ・失敗して取り消した作業・持ち主自身が書いたノート。
**書きすぎると読むコストが増えて、かえって使われなくなる。** 残す価値のあることだけ。

この2ファイルが無い vault（このキット以前に作られたもの）では、勝手に作らずに
「作業の履歴を残すファイルを作りますか？」と**一度だけ**聞く。断られたら二度と聞かない。

## 保存（`/vault-save`）

### 残すもの・残さないもの

| 残す | 残さない |
|---|---|
| 決まったこと | 雑談 |
| 分かったこと・調べた結果 | 途中の試行錯誤 |
| 手順・やり方 | 捨てた案 |
| 誰が何を言ったか | 同じことの言い換え |

会話の8割は残さなくていい。**残す価値のある2割を選ぶのがこの操作の本体。**

### 置き場所の決め方

1. `CLAUDE.md` のフォルダ表と照らす
2. 議事録なら議事録フォルダ、手順なら手順書フォルダ
3. **どれにも当てはまらなければ受信箱**。悩んで聞かない

> **受信箱が無い vault もある。** AI ナレッジウィキ型（`.raw/` と `wiki/` で構成される vault）には
> `01_受信箱` が存在しない。その場合は「素材なら `.raw/`、書いたものなら `wiki/` の該当フォルダ」に置く。
> 実際に存在するフォルダを `CLAUDE.md` とファイル一覧で確認してから決める。**無いフォルダに書き込まない。**

### 書き方

- 会話をそのまま貼らない。**3か月後の自分が読んで分かる形**に書き直す
- 冒頭に結論。経緯は後
- 人名・会社名・製品名は `[[名前]]` にする。リンク先のノートが無くてもよい（後で作られる）
- 出典を必ず書く（URL、ファイル名、会話の日付）
- frontmatter は `type` `created` `tags` で足りる。増やさない

### 既存ノートとぶつかったら

同名のノートがあれば、**新規作成せずに追記するかを聞く**。
追記するときは日付見出し（`## 2026-08-06`）を付けて、既存の記述を消さない。

## 質問に答える（`/vault-ask`）

### 探す順番

1. `hot.md`（あれば）— 直近の文脈
2. `index.md`（あれば）— 目次
3. ファイル名で当たりをつける
4. 全文検索
   ```bash
   grep -ril "検索語" --include="*.md" .
   ```
   Obsidian CLI が使えるなら（Obsidian が起動している必要あり）：
   ```bash
   obsidian search query="検索語" limit=10
   ```
5. 見つけたノートの**バックリンク**もたどる（関連が芋づるで出る）

### 答え方

- **根拠にしたノートを `[[ノート名]]` で必ず示す**
- vault に無いことは「vault には書かれていません」と言い切る。
  一般論を足すなら `※ここからは vault の外の一般的な話です` と区切る
- 2か所で食い違っていたら、**両方見せて更新日を比べる**。勝手に片方を採らない
- 見つからないときは、探した場所を挙げてから「無い」と言う。黙って一般論に流れない

これは検索ではなく**「自分が書いたものから答える」**という約束。ここを崩すと vault を持つ意味が消える。

## 点検（`/vault-lint`）

### 見つけ方

```bash
# ノート総数
find . -name "*.md" -not -path "./.obsidian/*" | wc -l

# リンクの抽出（[[...]] を集める）
grep -rho "\[\[[^]]*\]\]" --include="*.md" . | sort | uniq -c | sort -rn

# 受信箱の滞留（30日以上）
find ./01_受信箱 -name "*.md" -mtime +30

# 短すぎるノート
find . -name "*.md" -size -200c -not -path "./.obsidian/*"
```

リンク切れは、抽出したリンク名に対応する `.md` が存在するかを突き合わせて判定する。

> **判定の前に、次を必ず除外する。** 入れないと偽陽性だらけになり、報告が信用されなくなる。
> - **コードスパン・コードブロックの中の `[[`**（説明文で「`[[` と打つ」と書いてあるだけ）
> - `[[名前]]` `[[ ]]` のような**テンプレート内のプレースホルダ**
> - `|` を含むリンクは表示名を除いた**左側だけ**で判定する（`[[本名|表示名]]`）
> - 見出しへのリンク `[[ノート#見出し]]` は `#` の左側で判定する
>
> 迷ったら、そのリンクを含む行を一緒に表示して人が判断できるようにする。

### 判定から除外するもの（必ず守る）

次は**構造上そうなって当然**なので、問題として報告しない。
報告すると毎回同じ誤検出が並び、点検結果そのものが信用されなくなる。

| 除外するもの | どの項目から | 理由 |
|---|---|---|
| `_ログ.md` `_いまの文脈.md` | 孤立ノート・空のノート | AI が書く運用ファイル。リンクされなくて当然 |
| `00_はじめに.md` `CLAUDE.md` | 孤立ノート | 入口とルール。リンクされなくて当然 |
| `Templates/` 配下 | 孤立ノート・空のノート・重複 | ひな形。短くて当然、リンクもされない |
| `.obsidian/` 配下 | すべて | 設定ファイル。ノートではない |
| `.raw/` 配下（型E） | すべて | 原資料。immutable なので触らない |
| 説明文の中の `[[リンク]]` `[[名前]]` | リンク切れ | 書き方の説明であって実際のリンクではない |

チェック用のコマンド例（除外を含めた形）：

```bash
# 孤立ノート（運用ファイルとテンプレートを除く）
find . -name "*.md" \
  -not -path "./.obsidian/*" -not -path "./Templates/*" -not -path "./.raw/*" \
  -not -name "_*.md" -not -name "00_*.md" -not -name "CLAUDE.md"
```

**空のノートはバイト数で測らない。** 日本語は1文字3バイトなので、
`-size -200c` だと frontmatter だけで超えてしまい、中身のあるノートまで拾ってしまう。
**frontmatter と見出しを除いた本文の行数**で判定する。

```bash
# 空のノート＝本文（--- ブロックと # 見出しを除いた中身）が0行
find . -name "*.md" -not -path "./.obsidian/*" -not -path "./Templates/*" -not -name "_*.md" \
| while read -r f; do
    n=$(awk 'BEGIN{fm=0} /^---$/{fm++; next} fm==1{next} /^#/{next} /^[[:space:]]*$/{next} {c++} END{print c+0}' "$f")
    [ "$n" -lt 1 ] && echo "$f (本文なし)"
  done
```

**閾値は「本文0行」にする。** 1行でも書いてあれば価値がある。
「決まったこと: ○○」だけの議事録を「空」と報告すると、持ち主は点検を信用しなくなる。

### 出し方

**必ず先に一覧で見せて、承認を取ってから直す。**

- 件数 → 具体例 → 対応案 の順
- 「どれを直しますか？（番号 / 全部 / やめる）」で締める

### 触ってはいけないもの

- **削除**（本人の明示的な指示がある場合のみ）
- `.obsidian/` の設定
- フォルダ構成そのもの
- 本人が最近書いたノートの文面

### 直したあと

件数を報告して、**次に気をつけるといいことを1つだけ**添える。並べ立てない。

## 共通の原則

1. **持ち主が書いた文章を勝手に書き換えない。** 追記・移動も、まとめて何をするか伝えてから
2. **迷ったら受信箱。** 置き場所を聞かない
3. **フォルダを勝手に作らない。** 同種のノートが3つ以上たまってから提案する
4. **出典のないノートを作らない**
5. 操作のあと、何をしたかを**パス付きで**報告する
6. **作業したら `_ログ.md` に1行、区切りがついたら `_いまの文脈.md` を上書き**（冒頭の節を参照）
