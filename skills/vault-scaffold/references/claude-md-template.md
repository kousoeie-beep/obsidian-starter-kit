# 生成する `CLAUDE.md` のひな形

vault のルートに置く。Claude Code がこのフォルダで起動したとき自動で読まれる。
**`<用途>` にはユーザーが答えた言葉をそのまま入れる。** 言い換えない。本人の言葉が一番効く。

---

## 型 A / B / C / D 共通のひな形

```markdown
# この vault について

**目的：<用途>**

持ち主：<ユーザー名。分からなければ書かない>
作成日：<YYYY-MM-DD>

## フォルダの役割

| フォルダ | 何を入れるか |
|---|---|
| `01_受信箱` | 行き先が決まっていないもの。ここから他へ移す |
| `02_日々の記録` | デイリーノート（YYYY-MM-DD.md） |
| `03_ノート` | 育てるノート |
| `Templates` | ひな形 |
| `Attachments` | 画像・PDF |

<実際に作ったフォルダに置き換える>

## 書くときのルール

- **ファイル名は日本語でよい。** 分かりやすさを優先する
- **日付は `YYYY-MM-DD` で統一する**
- 人・会社・製品が出てきたら `[[名前]]` でリンクする。ノートが無ければ作ってよい
- frontmatter は最小限にする。`type` `created` `tags` があれば十分
- 見出しは `#` から始める。1ノートに `#` の見出しは1つ

## 作業したら記録する（あなたが書く）

この2つは**持ち主ではなく、あなた（AI）が書く。**

| ファイル | いつ | どう書くか |
|---|---|---|
| `_ログ.md` | ノートを作った・変えた・調べたとき | 日付見出しの下に**1作業1行**。関係するノートは `[[リンク]]` にする。**追記のみ**で過去の行は消さない |
| `_いまの文脈.md` | 会話が一区切りついたとき | **上書き**。500語以内。「次にこの vault を開いた自分」への引き継ぎとして書く |

### セッションの始めにやること

**まず `_いまの文脈.md` を読む。** 持ち主に「前回どこまでやったか」を説明させない。

### 記録しなくていいこと

- 検索しただけ、読んだだけ
- 失敗して取り消した作業
- 持ち主が自分で書いたノート（本人の作業は記録しない）

書きすぎると読むコストが増えて、かえって使われなくなる。**残す価値のあることだけ**を書く。

## AI（あなた）への指示

- **持ち主が書いたノートを勝手に書き換えない。** 追記や整理をするときは先に何をするか伝える
- 新しいノートは、その型のテンプレート（`Templates/`）に沿って作る
- どこに置くか迷ったら `01_受信箱` に置く。持ち主に聞かない
- 同じ種類のノートが3つ以上たまって、既存のフォルダに合わないときだけ、
  **新しいフォルダを提案する**（勝手に作らない）
- リンク切れや重複を見つけたら、直す前に一覧で見せる

## やらないこと

- ノートの削除（持ち主が明示的に頼んだときだけ）
- `.obsidian/` の設定変更（頼まれたときだけ。その際は Obsidian を終了してもらう）
- フォルダ構成の作り替え
```

## 型 D（チーム共有）で追記するもの

```markdown
## 共有ルール

- この vault は**チームで共有している**。個人の日記やプライベートなメモは置かない
- 他人が書いたノートを書き換えるときは、本人に確認する
- ノートには守秘レベルを書く：

| 値 | 意味 |
|---|---|
| `社外秘` | 社内のみ |
| `関係者のみ` | 特定の人だけ |
| `公開可` | 外に出してよい |

迷ったら `社外秘` にする。
```

## 型 E（AI ナレッジウィキ）のひな形

```markdown
# この vault について

**目的：<用途>**

Andrej Karpathy の LLM Wiki パターンで運用する。

## 構造

| 場所 | 役割 |
|---|---|
| `.raw/` | 原資料。**絶対に書き換えない。読むだけ** |
| `wiki/concepts/` | 概念・考え方 |
| `wiki/entities/` | 人・会社・製品 |
| `wiki/sources/` | 原資料1つにつき要約1ページ |
| `wiki/index.md` | 目次。ページを作ったら必ず更新する |
| `wiki/hot.md` | 直近の文脈。500語以内で上書きする |
| `wiki/log.md` | 追記のみ。**新しいものを先頭**に足す |
| `Templates/` | concept / entity / source のひな形 |

**この型には `01_受信箱` が無い。** 素材は `.raw/`、書いたものは `wiki/` に置く。

## 4つのサイクル

1. **Ingest** — `.raw/` に置かれた資料を読み、`wiki/sources/` に要約を作り、
   出てきた概念と固有名詞を `concepts/` `entities/` に切り出してリンクする
2. **Compile** — 既存ページとの矛盾・重複を見つけて統合する
3. **Query** — 質問には `hot.md` → `index.md` → 個別ページの順で読んで答える。
   **答えるときは必ずページ名を挙げる**（学習データではなく vault から答える）
4. **Lint** — 孤立ページ、リンク切れ、古くなった記述、抜けている相互参照を洗い出す

## ルール

- `.raw/` は immutable。整理した結果は必ず `wiki/` に書く
- 1ページ1トピック。長くなったら分割してリンクでつなぐ
- 出典のないページを作らない。どの原資料から来たかを必ず書く
- セッションの終わりに `hot.md` を更新する（次回の自分への引き継ぎ）

## この vault に入れないもの

個人の日記、プライベートなメモ、機密情報。
AI が書き足す vault と、自分の思考の vault は分ける。
```
