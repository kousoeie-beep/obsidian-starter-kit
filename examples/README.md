# サンプル

> ⚠️ **ここに入っているノート（田中さん・佐藤さん・案件A・案件B など）はダミーです。**
> **`/vault-init` で作ると、これらは入りません。** フォルダは空の状態で出てきます。
> ここにデータを入れてあるのは、リンクや一覧表の動きを**実際に見て確かめられるように**するためです。

## `/vault-init` が実際に作るもの

```
01_受信箱/        空
02_議事録/        空
03_案件/          空
04_手順書/        空
05_人と組織/      空
Templates/        ひな形5件（中身は空欄。{{title}} などが実行時に置換される）
Attachments/      空
00_はじめに.md    最初に読むノート
CLAUDE.md         AI 向けのルール
_ログ.md          「vault を作成しました」の1行だけ
_いまの文脈.md    「まだ中身はほとんどありません」
*.base            一覧表（データが増えると並び始める）
.obsidian/        設定済み
```

**ユーザーのノートは 0 件**の状態から始まります。用途に応じてフォルダ名やテンプレートの種類は変わります（5 つの型があります）。

## このサンプルの使いどころ

| 場面 | 使い方 |
|---|---|
| **動きを見せたい** | Obsidian で「フォルダを vault として開く」→ 選ぶ。`[[田中さん]]` をクリックしてバックリンクを見せると、リンクの意味が一発で伝わる |
| **一覧表を見せたい** | `議事録一覧.base` `案件一覧.base` を開く。データが入っているので表が並ぶ |
| **インストールが通らない人の救済** | ZIP にして渡す。Obsidian で開くだけで同じ状態から始められる |

```bash
cd examples && zip -r 仕事のナレッジ_サンプル.zip 仕事のナレッジ_サンプル
```

## 中身

| フォルダ | 型 | 元にした答え |
|---|---|---|
| `仕事のナレッジ_サンプル/` | B（仕事のナレッジ） | 「仕事のメモと議事録をためたい」 |

ダミーデータは、リンクが実際につながった状態にしてあります。

- 議事録 3 件 → 案件・人にリンク
- 案件 2 件（進行中 / 検討中）→ 一覧表のフィルタが効くのを確認できる
- 人 2 名 → バックリンクで「その人が出てくる会議」が並ぶ
